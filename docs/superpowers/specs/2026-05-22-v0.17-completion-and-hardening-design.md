# v0.17 — Completion + Hardening — Design Spec

## TL;DR

v0.17 ships four coordinated tracks that close the loop on v0.16's Tool Result Envelope work and harden the parts that real Windows usage exposed:

- **Track A — Telemetry completion.** Streaming LLM calls now log to `usage.jsonl` (B1, the reason `claudeCode` was missing from the activity panel). The "Savings" card switches from compression-only to **routing-based** measurement using a user-configurable baseline profile (`routingBaseline`, default `claudeCode`). `usage.jsonl` gains automatic in-place rotation at 10MB → 5MB so the file can't grow without bound.
- **Track B — GUI per-tool rendering.** The activity panel currently dumps the entire JSON envelope as a single string. v0.17 replaces that with per-tool views: `read_file` shows code with line numbers and a truncation banner; `list_files` shows a tree; `search_files` shows match snippets with the query highlighted; `run_command` shows terminal-style stdout/stderr with an exit-code badge. Failure envelopes get a uniform card with the error code as a badge plus a hint line.
- **Track C — Windows hardening + CI.** A GitHub Actions matrix gains `windows-latest`, so every PR runs the full test suite on Windows. `runChild()` gains explicit Windows shell quoting for `transport.command` paths that contain spaces. `workspaceBoundary`'s symlink-escape detection gets a junction-point test fixture to verify Windows reparse-point handling.
- **Track D — Tidy.** MCP server advertises `TIERKIT_VERSION` instead of the stale literal `"0.15.0"`. `docs/MCP_BRIDGE.md` is rewritten against v0.16's envelope shape. `read_file` returns `stale-cursor` (more informative) instead of `not-found` when the file behind a cursor was deleted.

## Why this exists (what was observed)

On Windows running v0.16, the user reported:

1. **`claudeCode` never appears in the activity-log panel** even when routing should have chosen it. Investigation: `openaiCompat.ts:385` calls `client.stream(...)` but never calls `appendUsage()`. Only the non-streaming `llmCall.ts:264` path logs. Streaming chat — which the GUI sidebar uses — produces no telemetry. (B1)
2. **"Today: Cloud input tokens saved — / Estimated cost saved —"** shows nothing despite real usage. The card is wired to `tierkit context compare` A/B results only, not to actual routing savings. Misleading labeling on a panel users open daily. (#1)
3. **Activity panel dumps raw envelope JSON.** v0.16's `tool-result-envelope.v1` is machine-readable for the model; humans get unreadable walls of JSON. (#2)
4. **Pre-existing concerns surfaced.** `usage.jsonl` has no rotation policy; MCP server advertises `version: "0.15.0"`; `docs/MCP_BRIDGE.md` describes the v0.15 result shape that no longer ships.

## Track A — Telemetry completion

### A.1 — Streaming usage logging (B1, the critical one)

Two streaming call sites:

- `packages/core/src/runtime/openaiCompat.ts:385` — `for await (const ev of client.stream(...))`. After the loop, before returning, append a `UsageRecord` to `usage.jsonl` (same shape as `llmCall.ts:249–264`).
- (Verify) any other `client.stream(` call sites — `grep -rn "client.stream(" packages/core/src/runtime/`. Each one needs `appendUsage`.

Stream events include `start`, `delta`, `usage`, `end`, `error`. The `usage` event carries `{ inputTokens, outputTokens }`; the `end` event carries `latencyMs`. Aggregate these across the stream and write one `UsageRecord` line at stream completion.

**Edge case — stream aborted by client:** if the iterator throws or the consumer breaks early, still write a partial record with the tokens received so far and `ok: false, failureCode: "stream-aborted"`. The activity panel needs to know the call happened even if it didn't complete.

**Test:** new vitest in `packages/core/test/openaiCompatUsageLog.test.ts` — drives a mocked `client.stream(...)` that yields the canonical event sequence; asserts one line appended to a temp `usage.jsonl` with the right shape.

### A.2 — Routing-based savings panel (#1)

**Config addition** to `tierkit.config.json`:

```jsonc
{
  "routingBaseline": "claudeCode"   // profileId of the baseline model
}
```

`packages/core/src/config/TierkitConfig.ts` gains a top-level optional `routingBaseline?: string`. Default when absent: `"claudeCode"` (the bundled flat-rate profile). When the named profile doesn't exist or has no cost data, the panel falls back to showing "(no baseline configured)" with a "Configure baseline" link.

**Calculation** — new helper `packages/core/src/runtime/routingSavings.ts`:

```ts
export interface RoutingSavingsSummary {
  baselineProfileId: string;
  baselineDisplayName: string;
  // Sum of (call.inputTokens + call.outputTokens) for local-device calls today.
  inputTokensRouted: number;
  outputTokensRouted: number;
  // Cost we would have paid if those tokens had gone to the baseline profile.
  estimatedCostSaved: number;
  // Number of local-device calls today (i.e. calls we routed away from cloud).
  cloudCallsAvoided: number;
}

export function computeRoutingSavings(
  records: UsageRecord[],
  baseline: ModelProfile,
  since: Date,
): RoutingSavingsSummary;
```

Logic: for each `UsageRecord` where `tier === "local-device"` AND `ok === true` AND `timestamp >= since`, sum `inputTokens` / `outputTokens` and accumulate `estimateCost(baseline, inputTokens, outputTokens)` into `estimatedCostSaved`. `cloudCallsAvoided` is the count of such records.

**HTTP endpoint** — `packages/core/src/runtime/Server.ts` adds `GET /v1/savings/today` returning:

```json
{
  "baselineProfileId": "claudeCode",
  "baselineDisplayName": "Claude Code",
  "inputTokensRouted": 12450,
  "outputTokensRouted": 980,
  "estimatedCostSaved": 0.0487,
  "cloudCallsAvoided": 7,
  "windowStart": "2026-05-22T00:00:00.000Z"
}
```

**GUI** — `gui.ts:744+` "Today" card body replaced. Pulls `/v1/savings/today` every 5s. Renders:

```
┌─ Today ─────────────────────────────────────┐
│ Cloud input tokens saved   12,450           │
│ Estimated cost saved       $0.0487          │
│ Cloud calls avoided        7                │
│ Baseline: Claude Code                       │
└─────────────────────────────────────────────┘
```

The old context-compression metrics get a smaller sub-card "Compression measurements (run `tierkit context compare` to populate)" lower in the same Settings tab. Existing wiring untouched.

**Internationalization:** new strings `cardSavingsTodayRouting`, `metricInputTokensSaved`, `metricCostSaved`, `metricCloudCallsAvoided`, `labelBaseline`, `hintBaselineNotConfigured` in both `RUNTIME.en` and `RUNTIME.ko`.

### A.3 — `usage.jsonl` auto in-place rotation

**Trigger** inside `appendUsage(filePath, record)` at `packages/core/src/runtime/usageLog.ts`. Before appending, if the file's size on disk exceeds `MAX_SIZE_BYTES = 10 * 1024 * 1024` (10 MB), invoke `trimUsageLog(filePath, TARGET_SIZE_BYTES = 5 * 1024 * 1024)`.

**Trim algorithm:**

```ts
async function trimUsageLog(filePath: string, targetBytes: number): Promise<void> {
  // 1. Read the whole file (acceptable since cap is ~10 MB).
  const raw = await fs.readFile(filePath, "utf8");
  // 2. Split into lines, drop trailing empty line.
  const lines = raw.split("\n").filter((l) => l.length > 0);
  // 3. Determine how many bytes to keep from the end of the lines array.
  let kept: string[] = [];
  let keptBytes = 0;
  for (let i = lines.length - 1; i >= 0; i--) {
    keptBytes += lines[i]!.length + 1;
    if (keptBytes > targetBytes) break;
    kept.unshift(lines[i]!);
  }
  // 4. Atomic write: tmp + rename.
  const tmp = `${filePath}.tmp-${process.pid}-${Date.now()}`;
  await fs.writeFile(tmp, kept.join("\n") + "\n");
  await fs.rename(tmp, filePath);
}
```

The size check before every append is cheap (one `stat`). Trim happens only when the threshold trips, then the file is back at ~5 MB and the next ~5 MB of appends accumulate before the next trim.

**Test:** seed a file at >10 MB, append once, assert file is now <6 MB and the most recent entries are preserved.

## Track B — GUI per-tool rendering

### B.0 — Common shell (applies to all tools)

Every envelope rendered in the activity panel uses the same header structure:

```
┌─ {icon} {tool} · {keyArg} ── [{statusBadges}]
│ {tool-specific body}
├─ {hintLine} (optional)
└─
```

- `icon`: 📄 for read_file, 📁 for list_files, 🔍 for search_files, ⚡ for run_command, ✏️ for write_file/apply_diff (existing v0.15 tools also gain this), etc.
- `tool`: bare tool name (`read_file`, NOT `tierkit.read_file` — the MCP prefix is implicit context)
- `keyArg`: single most-relevant arg (`path` for read_file/list_files; `pattern` for search_files; `command` truncated to 40 chars for run_command)
- `statusBadges`:
  - Success non-truncated: `[ok]` (subdued green)
  - Success truncated: `[truncated · {N} more]` (amber)
  - Warnings present: `[⚠ warning]` (amber)
  - Failure: `[❌ {error.code}]` (red)

### B.1 — `read_file` view

Success (full read):
```
┌─ 📄 read_file · src/foo.ts ────────────── [ok · 56 lines]
│   1  import dgram from "node:dgram";
│   2  ...
│  56  ...
```

Success (truncated):
```
┌─ 📄 read_file · src/foo.ts ────────────── [truncated · 600 more]
│ Lines 1–300 of 900 returned (600 more, 1273 bytes)
│   1  import dgram from "node:dgram";
│   2  ...
│ 300  ...
├─ Next: read_file(cursor=eyJ…) [Copy cursor] [▶ Continue]
```

The "▶ Continue" button issues `POST /v1/tool-call` with `tool: "tierkit.read_file"` and `args: { cursor: <decoded> }` and inserts the new envelope as a child card under the original. Pagination chain visible.

Failure (stale-cursor):
```
┌─ 📄 read_file · src/foo.ts ────────────── [❌ stale-cursor]
│ file fileHash changed since cursor was issued
├─ Hint: re-read from beginning (no cursor)
```

Success with broad-pattern warning:

### B.4 — `run_command` view

Success:
```

│ STDOUT (4.2 KB)
│   PASS test/foo.test.ts
│   Tests: 1 passed

```

Success with truncated output:
```

│ STDOUT (64 KB returned · 142 KB total)
│   …content…
│ STDERR (empty)

```

Failure (command-blocked):
```

│ command is hard-blocked by Tierkit policy: dangerous-pattern
```

```

│ command requires approval: classifier severity 'warn'
│ v0.16+ does not execute approval-required commands through MCP yet
├─ Hint: run the command yourself in your shell
```

### B.5 — Failure envelopes (generic)

Any tool's failure envelope (`ok: false`, `error: { code, message }`) renders with the same shape:

```
┌─ {icon} {tool} · {keyArg if any} ── [❌ {error.code}]
│ {error.message}
├─ Hint: {code-specific hint, optional}
```

Hint table (rendered when the code is known):

| `error.code` | Hint |
|---|---|
| `not-found` | (no hint — message is self-explanatory) |
| `not-a-file` | `Pass a regular file path, not a directory` |
| `not-a-directory` | `Pass a directory path, not a file` |
| `path-escape` / `outside-workspace` | `Path must stay within the workspace` |
| `ignored-path` | `This path is on the ignore/denylist` |
| `sensitive-file-blocked` | `This path matches a sensitive-file pattern` |
| `invalid-args` | `Check the required arguments` |
| `invalid-query` | `Pattern is empty or invalid regex` |
| `cursor-invalid` | `Re-issue the read without cursor` |
| `stale-cursor` | `File changed; re-read from beginning (no cursor)` |
| `payload-corrupt` | `Patch payload sha256 mismatch — re-propose the patch` |
| `payload-missing` | `Patch payload sidecar missing — re-propose the patch` |
| `command-blocked` | (no hint — Tierkit policy is firm) |
| `approval-required` | `Run the command yourself in your shell` |
| `command-timeout` | `Increase transport.timeoutMs or narrow the command` |
| `spawn-failed` | `Verify the CLI binary is on PATH and executable` |
| `dangerous-command-blocked` | `Tierkit policy blocked: review and run manually if intended` |

Unknown codes (forward-compat): show error.code badge but no hint line.

### B.6 — Markup vs syntax highlighting

v0.17 does NOT bundle a syntax highlighting library. Code blocks in `read_file` results render in a `<pre>` with line numbers and a `monospace` font. No tokenizing, no color. The reason: bundle size + complexity vs marginal UX gain. v0.17.1 may add lazy-loaded Prism.js if users request it.

`search_files` query highlighting is the one exception — it uses simple `<mark>` tags over escaped regex matches. No tokenizer, no language detection. Just visual emphasis on the matched text.

### B.7 — Failure envelope cards in the activity panel

The current activity panel already renders one card per tool call. v0.17:
- Detects `result.version === "tool-result-envelope.v1"` and dispatches to per-tool renderer
- Detects `result.ok === false` and uses the generic failure card with the hint table
- Falls back to v0.15-shape rendering for tools that don't migrate (propose_patch, apply_patch, get_policy_status, task_complete, ask_followup_question) — they still return plain objects, not envelopes

## Track C — Windows hardening + CI

### C.1 — GitHub Actions cross-OS matrix

New workflow `.github/workflows/ci.yml`:

```yaml
name: CI
on:
  pull_request:
  push:
    branches: [main]

jobs:
  test:
    runs-on: ${{ matrix.os }}
    strategy:
      fail-fast: false
      matrix:
        os: [ubuntu-latest, macos-latest, windows-latest]
        node: ['20']
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: ${{ matrix.node }}
      - uses: pnpm/action-setup@v4
        with:
          run_install: false
      - run: pnpm install --frozen-lockfile
      - run: pnpm build
      - run: pnpm test
    timeout-minutes: 15
```

`fail-fast: false` so a Windows-only failure doesn't block Linux/macOS feedback. `timeout-minutes: 15` since Windows runners are slower.

The existing release.yml stays on `ubuntu-latest` (tag push only — no need to package vsix on all 3 OS).

### C.2 — `runChild` Windows quoting (B8)

When `shell: process.platform === "win32"` and `transport.command` contains spaces (e.g., `C:\Program Files\Node\node.exe`), Node's spawn delegates to `cmd.exe /d /s /c "<concat>"` and the concat breaks at the first space.

Fix in `packages/core/src/model/providers/runChild.ts`:

```ts
function quoteForWindowsShell(s: string): string {
  // cmd.exe /c "<concat>" — single double-quote pair is the safest form.
  // Escape any literal `"` inside the string with `""` (cmd.exe convention).
  if (!/[\s&|<>^"]/.test(s)) return s;
  return `"${s.replace(/"/g, '""')}"`;
}

export function runChild(command: string, args: string[], opts: RunChildOptions = {}): ChildProcess {
  const isWin = process.platform === "win32";
  const cmd = isWin ? quoteForWindowsShell(command) : command;
  const finalArgs = isWin ? args.map(quoteForWindowsShell) : args;
  return spawn(cmd, finalArgs, {
    ...opts,
    shell: isWin,
    env: mergeEnv(process.env, opts.callerEnv),
  });
}
```

`quoteForWindowsShell` only quotes when the string contains shell-meaningful characters. macOS/Linux pass through unchanged (`shell: false`).

**Test:** `runChild.test.ts` gains:
- `quoteForWindowsShell` unit tests covering: no special chars (passthrough), spaces (quoted), embedded quotes (escaped), pipe characters (quoted).
- A Windows-only integration test (skipped on non-Windows) that spawns a command from a path with a space and verifies it runs.

### C.3 — `workspaceBoundary` junction-point verification (B7)

`fs.realpathSync` on Windows resolves both symlinks (`mklink`) and junction points (`mklink /J`) per Node docs ≥14. v0.17 adds a Windows-only test fixture that:

1. Creates a directory outside the workspace.
2. Creates a junction inside the workspace pointing to the outside dir using `fs.symlinkSync(target, link, 'junction')` (the `'junction'` type works on Windows; throws on macOS/Linux and the test is skipped there).
3. Calls `resolveUnderWorkspace(workspace, "the-junction")`.
4. Asserts it throws with `path-escape` error.

Wrapped in `it.runIf(process.platform === "win32")` or vitest's `describe.runIf(...)` so non-Windows runs skip cleanly.

If the test fails (junction-point not resolved by `fs.realpathSync`), v0.17.1 needs a custom resolver. The current spec assumes it works per Node docs — verification only.

### C.4 — Doctor check: subprocess command path with spaces

`packages/core/src/usecases/doctor.ts` gains a new check that scans all subscription-CLI profiles' `transport.command` values. If any contains spaces (e.g., `C:\Program Files\...`), emit:

```
WARNING: profile <id> transport.command contains spaces: <path>.
This can break on Windows shell:true spawning. Consider moving the
binary to a path without spaces, or letting runChild's quoting handle
it (verified in tests for v0.17+).
```

Surfaces the risk early without blocking the call (quoting in C.2 SHOULD handle it).

## Track D — Tidy

### D.1 — MCP server version (B2)

`packages/mcp-server/src/server.ts:247`:

```ts
// Before:
new Server({ name: "tierkit", version: "0.15.0" }, ...)
// After:
import { TIERKIT_VERSION } from "@tierkit/core";
new Server({ name: "tierkit", version: TIERKIT_VERSION }, ...)
```

`TIERKIT_VERSION` already exists in `@tierkit/core` and is bumped by `pnpm bump`. The MCP protocol-level version stays in sync automatically.

### D.2 — `docs/MCP_BRIDGE.md` rewrite (B4)

The v0.15 version describes the old result shape (ad-hoc `{ ok, content, ... }`). v0.17 rewrites to:

- Show the v0.16 `tool-result-envelope.v1` schema with a concrete example for each tool
- Document the cursor pagination contract (`truncated → next.cursor → continue`)
- List the full v0.17 error code table (the same one in this spec's B.5)
- Add a "Migration from v0.15" section for any external MCP client that built against the old shape

### D.3 — `read_file` returns `stale-cursor` on file-deleted-during-cursor-validation (B5)

`packages/agent/src/tools/readFile.ts` cursor branch around the fileHash check. When `sha256OfFile(absPath)` throws `ENOENT`, the current code returns `not-found`. v0.17 returns `stale-cursor` with message `"file behind cursor was deleted"`. The user/model can interpret this the same way as a hash mismatch — retry without cursor or with a different path.

Same change to `packages/mcp-server/src/tools/readFile.ts` (MCP-side mirrors).

**Test:** new cases in both `readFileEnvelope.test.ts` test files: issue cursor → delete file → call again → expect `stale-cursor`.

## Acceptance criteria (release-ready)

1. **Track A.1** — streaming chat against `claudeCode` profile produces a line in `usage.jsonl` with the same shape as `chat()`. Verified by `openaiCompatUsageLog.test.ts`.
2. **Track A.1** — partial stream (consumer breaks mid-stream) still writes a record with `ok: false, failureCode: "stream-aborted"`.
3. **Track A.2** — `/v1/savings/today` returns the routing-savings summary using the configured `routingBaseline`. The GUI panel shows non-`—` values when local-device calls exist in today's `usage.jsonl`.
4. **Track A.2** — when `routingBaseline` is unset, GUI shows "(no baseline configured)" with a link to Settings.
5. **Track A.3** — `usage.jsonl` size never exceeds ~10 MB under normal use; after a forced trim the file is ≤ ~6 MB and the most recent entries are preserved. Verified by a vitest that seeds >10 MB and checks post-append size.
6. **Track B** — every long-output tool (read_file, list_files, search_files, codebase_search, run_command, execute_command) has a custom render template in the GUI. Raw JSON envelope is never visible in the activity panel.
7. **Track B** — failure envelopes show the error code as a red badge and the message + hint (if known code) in the body. Unknown codes show the code badge but no hint.
8. **Track C.1** — GitHub Actions PR run executes on `ubuntu-latest`, `macos-latest`, AND `windows-latest`. All three must pass for merge.
9. **Track C.2** — `runChild()` quotes Windows shell args. A command path containing a space (e.g., `C:\Program Files\Node\node.exe`) runs successfully via `shell: true` on Windows.
10. **Track C.3** — `workspaceBoundary` test fixture verifies junction-point escape detection on Windows. Test is conditionally skipped on macOS/Linux.
11. **Track C.4** — `tierkit doctor` surfaces a warning when a subscription-CLI profile's `transport.command` contains spaces.
12. **Track D.1** — `tierkit mcp serve` advertises the current `TIERKIT_VERSION`. Verified by inspecting the MCP `initialize` handshake response.
13. **Track D.2** — `docs/MCP_BRIDGE.md` describes the v0.16 envelope shape with a working example for each of the 7 tools.
14. **Track D.3** — `read_file` with a cursor whose target file was deleted between issue and reuse returns `stale-cursor` (not `not-found`). Same on the MCP side.
15. **Regression** — all existing v0.16 tests still green. Pre-existing `@tierkit/client/openaiCompat.test.ts:75` failure (HTTP 400 vs 404, present at v0.15 baseline) remains a known unrelated issue.

## Out of scope / deferred

- **Syntax highlighting in `read_file` GUI view** — v0.17.1 if users request it.
- **Stable workspace-snapshot cursor for `search_files`** — defer to v0.18; v0.17 keeps best-effort pagination.
- **Time-based or count-based log rotation** — v0.17 ships only size-based auto-trim. Time-based is a v0.17.1+ candidate.
- **`run_command` `read_command_output` follow-up tool** for paginating subprocess output — already deferred from v0.16; remains deferred.
- **`pdf` / `ipynb` / binary file handling in `read_file`** — out of scope for v0.17.
