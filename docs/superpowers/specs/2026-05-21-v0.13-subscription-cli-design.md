# v0.13 — Subscription CLI Provider (Claude Code)

**Status:** design approved · 2026-05-21
**Scope:** v0.13.0 ships Claude Code as the first subscription-CLI provider. v0.13.1 will add Codex CLI on the same `SubscriptionCliProvider` base.

---

## 1. Why this exists

Tierkit v0.12.3 routes Roo / Cline / Continue through the OpenAI-compatible loopback, but observed behavior is that requests keep landing on `qwen2.5-coder:7b` (local Ollama) even when the user wanted a higher-quality model. Two root causes:

1. **No subscription-CLI provider exists.** `pickProviderClient()` only recognizes `ollama`, `openai`/`openai-compatible`, `anthropic`, `mock`. A profile with `provider: "claude-code"` would return `undefined` and the call fails — so users never configured one.
2. **Pinned profiles silently fall back to local.** `buildEscalationChain()` has a tail-fallback that, when a user pins `model: "claudeSonnet"` but `ANTHROPIC_API_KEY` is unset, walks down to `localCoder`. The user gets a local answer with no signal that their explicit choice was ignored.

v0.13 fixes both. It also adds a third lever the routing reorder noted in `SPEC.md:86`: within a tier, prefer `paymentModel: free → flat-rate → per-token`. That lets a Claude Code subscription beat a per-token Anthropic API call inside the same risk tier — which is what users want when they're paying for the subscription anyway.

## 2. Non-goals (v0.13.0)

These are explicitly out of scope and will be revisited later:

- **Tool-call bridging.** Roo / Cline send `tools: [...]` and expect `tool_calls` in the response. The `claude` CLI in headless mode does its own tool orchestration internally and returns text only. v0.13.0 forwards no tools to subscription CLI providers and always returns `tool_calls: []`. Subscription CLI profiles are positioned as planners / reviewers — the calling agent runs its own tool loop using the returned text. v0.13.1+ will evaluate whether a structured bridge is worth building.
- **Codex CLI.** Same architecture, scheduled for v0.13.1 once Claude Code is shipped and the abstract base is shaken out.
- **Native streaming from subprocess providers.** `claude -p --output-format=stream-json` emits a non-SSE format. v0.13.0 collects the full response, then degrades the SSE response to a single delta + end, with `tierkit.warning: "stream-degraded-to-non-stream"`.
- **Telemetry / cloud sync / auto-verdict.**
- **CLI auth token storage or scraping CLI config.**

## 3. Architecture

```
Roo / Cline / Continue
      │
      ▼
runtime/openaiCompat.ts
      │
      ├─ pinned (model: "claudeCode" or any explicit id)
      │     └─ viability check → fail-loud (no fallback)
      │
      └─ auto (model: "auto" | "tierkit")
            └─ runtime/proxy/autoResolver.ts
                  └─ decideRoute → buildEscalationChain
                        (tier chain unchanged: local → private-remote → public-cloud,
                         with tail-fallback below primary preserved for auto)
                  └─ sortProfilesForTier:
                        primary key   = paymentModel rank (free=0, flat-rate=1, per-token=2)
                        secondary key = goodAt fit / neutral / anti-fit
                        tertiary      = declaration order
                  └─ partitionByViability prune
      │
      ▼
runtime/proxy/llmCall.ts
      │ (redaction · budget · session · approval gates — all pre-provider, unchanged)
      ▼
model/providers/index.ts → pickProviderClient(profile)
      │
      └─ provider === "claude-code" → new ClaudeCodeProvider
            (extends SubscriptionCliProvider)
      │
      ▼
spawn(profile.transport.command, profile.transport.args)
      │ stdin: serialized messages
      │ stdout: { "type":"result", "result":"...", "usage":{...} }
      ▼
ChatResult { content, inputTokens, outputTokens, usageSource, paymentModel:"flat-rate" }
      │
      ▼
usageLog.ts → usage.jsonl  (costUsd: 0; flat-rate)
      │
      ▼
OpenAI chat.completions response
      └─ tool_calls: [] always
      └─ tierkit: { profileId, usageSource, warning? }
```

Tool / bash execution paths in the agent layer continue to be gated by `command-gate` — that gate is **not** the path that wraps the subprocess CLI itself. The subprocess CLI is a model-call; the user's commands are gated where they always were.

## 6. Routing changes

### 6.0 `effectivePaymentModel` — single source of truth

`paymentModel` (router sort key) and `cost` (budget display) are **two separate fields** in `ModelProfile`. `effectivePaymentModel(profile)` is unchanged from v0.12 and is the only function router code consults for ordering:

```
1. profile.paymentModel set?      → use it
2. otherwise derive from kind:
     local-device   → "free"
     private-remote → "free"
     public-cloud   → "per-token"
```

`cost.type` is **not** read by the router. It is for budget display and per-call cost calculation only. The `claudeCode` bundled profile (see §9.1) sets `paymentModel: "flat-rate"` explicitly and omits `cost` — the subscription is paid out of band, so per-call `costUsd` is `0`.

### 6.1 `sortProfilesForTier` — paymentModel becomes primary key

Current:
```
rank(p) = goodAt-fit(0) / neutral(1) / anti-fit(2)
sort: rank ASC, then declaration order
```

New:
```
keys(p) = (
  paymentModelRank(p),         // free=0, flat-rate=1, per-token=2
  goodAtRank(p, taskType),     // 0/1/2 as before
  declarationIndex,
)
sort: lexicographic
```

`paymentModelRank(p)` uses `effectivePaymentModel(p)`. Tier ordering (local → private-remote → public-cloud) is unchanged — it lives in `buildEscalationChain`, not here. Tail-fallback into lower tiers (for auto) is unchanged.

### 6.2 Pinned profile path — no silent fallback

In `openaiCompat.ts`, when `model` is not `auto` / `tierkit`:

```
1. profile = profiles[model]
   missing → 404 invalid_request_error
2. v = checkProfileViability(profile, env)
   not viable → 502 (504 for cli-timeout) with body:
     {
       error: {
         type: "profile_not_viable",     // or "profile_timeout"
         profileId, reason, message
       }
     }
   message contains no external URLs
3. proceed with [model] as the single candidate; executeLlmCall does NOT
   walk further candidates for pinned requests
```

`auto` keeps its existing escalation + tail-fallback semantics. The breaking change applies to **all pinned profiles** (not just subscription CLI) — Tierkit's value is "explainable routing", and silent fallback violates that.

### 6.3 Stream-true behavior

Selected provider is chosen **without** considering streaming capability — the user's `#7` correction. The decision tree:

```
stream:true
  candidate = first viable from existing routing order
  if candidate.transport?.type === "subprocess":
    run chat() then emit a single-delta SSE stream:
      [chunk { delta: { role: "assistant" } }]
      [chunk { delta: { content: <full text> } }]
      [chunk { usage }]
      [chunk { finish_reason: "stop" }]
      [DONE]
    the first chunk and the final/usage chunk carry:
      tierkit: { profileId, usageSource, warning: "stream-degraded-to-non-stream" }
    middle delta chunks MAY omit the envelope to stay closer to the
    OpenAI-compatible wire format
  else:
    native streaming as today
```

No reordering. No `preferNativeStreaming` config option — it can be added later if real usage demands it.

Tests assert the warning is present "at least in the first chunk and a final/usage chunk" rather than "in every chunk", so the implementation can adjust where it puts the envelope without breaking tests.

## 7. Subscription CLI provider runtime

### 7.1 `subscriptionCli.ts` (abstract base)

```ts
export interface SubscriptionCliParsedResult {
  content: string;
  inputTokens?: number;
  outputTokens?: number;
  raw: unknown;
}

export abstract class SubscriptionCliProvider implements ProviderClient {
  abstract buildArgs(profile: ModelProfile): string[];
  abstract parseStdout(stdout: string): SubscriptionCliParsedResult;

  async probe(profile, env): Promise<ProbeResult> {
    // spawn(command, transport.healthCheckArgs, { timeout: 1500ms })
    // ENOENT          → { ok: false, code: "cli-not-found", message }
    // exit !== 0      → { ok: false, code: "cli-healthcheck-failed", message }
    // exit === 0      → { ok: true, latencyMs }
    // stdout emptiness is NOT checked
  }

  async chat(profile, request, env): Promise<ChatResult> {
    const prompt = serializeMessages(request.messages);
    const { stdout, stderr, code, timedOut, truncated } = await spawnWithStdin(
      profile.transport.command,
      this.buildArgs(profile),
      prompt,
      {
        timeoutMs: profile.transport.timeoutMs,
        maxStdoutBytes: profile.transport.maxStdoutBytes,
        maxStderrBytes: profile.transport.maxStderrBytes,
      },
    );
    if (timedOut) throw new ProviderError("cli-timeout", stderr || "subprocess exceeded timeoutMs");
    if (truncated) throw new ProviderError("cli-output-too-large", "stdout exceeded maxStdoutBytes");
    if (code !== 0) throw new ProviderError("cli-exit-nonzero", stderr || `exit ${code}`);

    let parsed: SubscriptionCliParsedResult;
    try { parsed = this.parseStdout(stdout); }
    catch {
      const trimmed = stdout.trim();
      if (!trimmed) throw new ProviderError("cli-empty-output", stderr || "empty stdout");
      parsed = { content: trimmed, raw: stdout };
    }
    if (!parsed.content) {
      throw new ProviderError("cli-empty-output", stderr || "parser returned empty content");
    }

    const hasFullUsage =
      Number.isFinite(parsed.inputTokens) && (parsed.inputTokens as number) >= 0 &&
      Number.isFinite(parsed.outputTokens) && (parsed.outputTokens as number) >= 0;

    const inputTokens  = hasFullUsage ? parsed.inputTokens! : estimateTokensFromText(prompt);
    const outputTokens = hasFullUsage ? parsed.outputTokens! : estimateTokensFromText(parsed.content);
    const usageSource: "provider-reported" | "estimated" = hasFullUsage ? "provider-reported" : "estimated";

    return {
      ok: true,
      content: parsed.content,
      inputTokens,
      outputTokens,
      provider: profile.provider,
      model: profile.model,
      usageSource,
      latencyMs,
    };
  }

  async *stream(profile, request, env): AsyncIterable<StreamEvent> {
    // Single-shot: collect via chat(), emit start → delta(full text) → usage → end
    // openaiCompat is responsible for adding `tierkit.warning` envelope.
  }
}
```

`serializeMessages(messages)` preserves all roles for multi-turn context. Format (role blocks joined with `\n\n`):

- `System:` for system/developer messages
- `User:` for user messages
- `Assistant:` for assistant messages
- `Tool result:` for tool messages

The `tool` role keeps the OpenAI-compatible distinction visible in the prompt even though we forward no tool definitions; multi-turn agent traces stay legible to the CLI.

### 7.2 `claudeCode.ts`

```ts
export class ClaudeCodeProvider extends SubscriptionCliProvider {
  buildArgs(profile: ModelProfile): string[] {
    return [...(profile.transport!.args ?? [])];
  }

  parseStdout(stdout: string): SubscriptionCliParsedResult {
    const trimmed = stdout.trim();
    let raw: unknown;
    try { raw = JSON.parse(trimmed); }
    catch {
      return { content: trimmed, raw: trimmed };
    }
    const r = raw as Record<string, unknown> | null;
    const content =
      (r && (r.result ?? r.content ?? r.text ?? r.message)) ?? trimmed;

    const usage = (r && r.usage) as Record<string, unknown> | undefined;
    const inputTokens  = pickNonNegativeNumber(usage?.input_tokens, usage?.inputTokens);
    const outputTokens = pickNonNegativeNumber(usage?.output_tokens, usage?.outputTokens);

    return {
      content: typeof content === "string" ? content : JSON.stringify(content),
      ...(inputTokens  !== undefined ? { inputTokens  } : {}),
      ...(outputTokens !== undefined ? { outputTokens } : {}),
      raw,
    };
  }
}
```

The parser is intentionally permissive — Claude Code CLI's `--output-format=json` shape can shift between releases. Unknown shapes fall through to "treat stdout as content, estimate tokens."

### 7.3 `estimateTokens.ts`

Self-contained, no external deps:

```ts
export function estimateTokensFromText(text: string): number {
  if (!text) return 0;
  let cjk = 0;
  for (const ch of text) {
    const cp = ch.codePointAt(0)!;
    // CJK Unified Ideographs, Hangul Syllables, Hiragana, Katakana
    if (
      (cp >= 0x3040 && cp <= 0x30FF) ||
      (cp >= 0x3400 && cp <= 0x9FFF) ||
      (cp >= 0xAC00 && cp <= 0xD7A3)
    ) cjk++;
  }
  const nonCjk = text.length - cjk;
  return Math.max(1, Math.ceil(cjk / 2 + nonCjk / 4));
}
```

Justification recorded in §7.3 of the conversation: Claude tokenizer differs from OpenAI's anyway, flat-rate doesn't need precise per-call cost, and dependency-free keeps bundle / maintenance small.

### 9.2 `migrateSeedDefaultDisabled.ts`

Runs once per profile per workspace, on-load, after the existing v0.12.3 migrations:

```
for each bundled profile with defaultDisabled: true:
  if profile.id is in migrations.defaultDisabledSeededProfileIds:
    skip       # already seeded once; respect user's later enable/disable
  else:
    if id not in disabledProfileIds:
      push id to disabledProfileIds
    push id to migrations.defaultDisabledSeededProfileIds
```

After this runs once, the user is free to enable or disable as they wish — the seeder never touches the profile again. The marker survives across upgrades, so re-running the seeder on a future version does nothing unless **new** `defaultDisabled` profiles arrive (e.g., v0.13.1 ships `codexCli` with `defaultDisabled: true` → it gets seeded on first load of v0.13.1).

## 11. Behavior change handling

This is a real breaking change for users who pinned `claudeSonnet` or `gpt4o` without keys. Four notice surfaces:

1. **CHANGELOG (required):**
   ```
   BREAKING: Pinned model profiles no longer silently fall back to local profiles.
   A pinned profile that fails viability (missing API key, missing CLI binary, etc.)
   returns HTTP 502 with `{ error: { type, profileId, reason, message } }`.
   Use `model: "auto"` to allow router-driven fallback.
   ```
2. **`tierkit doctor` warning:** new check `pinned-profile-fallback-disabled`. Inspects connected tool configs the daemon knows about (`tierkit plugin` adapters) and warns when any pin a profile whose viability check currently fails.
3. **First-start INFO log** (`runtime/Server.ts` startup): one line on daemon start when the version transitions to `0.13.x` (gated by a marker in `.tierkit/runtime.state.json` or similar — implementation detail; reuse an existing version marker if available):
   ```
   [info] v0.13: pinned profiles no longer fall back to local. Use model:"auto" for fallback routing.
   ```
4. **One-time GUI banner** (see §10.3).

The four surfaces are intentional — CLI-only users see #1–#3; GUI users see #4.

## 14. Acceptance criteria

The release is done when **all** of the following hold:

1. `tierkit doctor` passes on a clean workspace.
2. `tierkit route explain "review this project" --mode review` shows each profile with selected/skipped + reason. The risk scorer must already lift this kind of task into `private-remote` as the primary tier; given that and a workspace with Claude Code installed and `claudeCode` enabled, `route explain` output ranks `claudeCode` ahead of per-token private/public-cloud profiles (paymentModel: flat-rate beats per-token), and selects `claudeCode` first.
3. A Roo / Cline / Continue request with `model: "auto"` to the OpenAI-compatible endpoint, on a workspace where the user has enabled `claudeCode` and the `claude` CLI is on PATH, results in a `claude` subprocess invocation visible in `usage.jsonl` and a coherent text response back to Roo.
4. The same request with `model: "claudeCode"` succeeds in the same scenario.
5. The same request with `model: "claudeCode"` on a workspace where `claude` is NOT on PATH returns HTTP 502 with `{ error: { type: "profile_not_viable", profileId: "claudeCode", reason: "cli-not-found", message } }`, and `localCoder` is NOT invoked.
6. The same request with `model: "auto"` in scenario #5 falls through to the next viable candidate (possibly `localCoder`) and the response carries `tierkit.profileId` indicating what served the request.
7. A `stream: true` request that selects a subprocess profile emits a valid OpenAI-compatible SSE stream carrying `tierkit.warning: "stream-degraded-to-non-stream"` on every chunk, and the selected provider is **the same** as it would be with `stream: false`.
8. Existing local-Ollama-only setups (no `claudeCode` enabled, no API keys) behave exactly as in v0.12.3 — the only visible difference is the GUI banner on first load.
9. All tests listed in §12.1 pass.
10. `pnpm typecheck`, `pnpm lint`, `pnpm test` all clean across the monorepo.
