## §1. Identity & scope

**Theme:** Make the v0.11/v0.12 measurement loop runnable from the Cost Control sidebar with **zero terminal**.

**One-line:** Build → see selected files & estimated savings → confirm cost → run compare with live streaming → see actual savings table → save a human quality verdict. All in the GUI.

**Why now:** v0.12 made the data layer (paymentModel + budget caps) but the *experience* of cost savings is still CLI-only. For real product validation, users need to see savings + run compare + record quality judgment in the GUI. The verdict captured here is the data that gates **v0.14** entry (local LLM rerank/compress) — the same context-compression 5-task validation gate documented in the v1.7-spike validation log. v0.13 (subscription CLI subprocess provider) is a much larger structural addition; doing it before users can actually run validation in the UI risks investing in the wrong direction.

**Scope (additive only):**

- 5 new HTTP routes under `/v1/context/*` (`build`, `:id`, `recent`, `:id/compare`, `:id/verdict`)
- SSE event protocol for the compare endpoint (live phase / delta / side-result / compare-done / error)
- Sidecar `verdict.json` next to `artifact.json` in `.tierkit/runtime/context-artifacts/<id>/`
- One new GUI card: "Current project — validation" (activates the inert stub from v0.11.2)
- Cost confirmation modal before compare execution; `{ confirm: true }` enforced at HTTP layer
- 6 deferred policies pinned at the API layer:
  1. `POST /v1/context/:id/compare` requires `{ confirm: true }` body — no auto-execution. Without confirm → `412 confirm-required` with `estimated` payload (the 412 IS the modal preview)
  2. Same artifact cannot run two simultaneous compares — second request returns `409 compare-already-running`
  3. SSE client disconnect → server `AbortController.abort()` on the in-flight compare; no background continuation; no daemon-restart job-resume
  4. `POST /v1/context/:id/verdict` requires `artifact.compare !== undefined` — else `409 compare-not-run`. Verdict is sidecar-only — no `ContextArtifact` schema change
  5. After SSE headers are sent, all errors become SSE `error` events. Pre-stream errors (404/412/409/400) only happen before headers
  6. Verdict file is rewriteable (last-write-wins); `reviewedAt` always server-stamped at write time

**Out of scope:**
- Subscription CLI subprocess provider → **v0.13**
- Routing reorder (free → flat-rate → per-token) → v0.13
- Local LLM rerank/compress → **v0.14**
- `POST /v1/context/:id/send` endpoint + `[Send compressed only]` UI button → v0.12.3 if validation reveals demand
- `[Open prompt.md]` (file open via webview message bridge or HTTP file serve) → v0.12.3+
- CLI `tierkit verdict` commands — not planned (verdict is a UI-only concern)
- `ContextArtifact` schema change — verdict is sidecar; no `schemaVersion` bump
- Cross-session job queue, WebSocket pub-sub, daemon-restart job resume — non-goal by principle (in-process loopback only)
- LLM-based auto-verdict — non-goal; the human verdict IS the validation gate

**v0.12.2 user outcome:**
1. Open VS Code sidebar → Cost Control
2. Type a task into the validation card → click "Build compressed context"
3. See selected files + token estimates inline
4. Click "Compare baseline vs compressed" → see modal with estimated cost → click "Run compare"
5. Watch the two responses stream in real time (SSE)
6. See actual savings table (tokens, cost, latency)
7. Click `Same / Better / Worse / Unusable` → click "Save verdict"
8. Verdict persists at `.tierkit/runtime/context-artifacts/<id>/verdict.json`

The aggregated verdicts are the input to the v0.14 entry-gate validation-log compilation. Compiling that log is **not** in v0.12.2 scope; it's manual today and could be automated in v0.13 polish if useful.

## §2. HTTP endpoints

All 5 routes under `/v1/context/*`. Existing dispatch pattern (`route === "METHOD /v1/path"`). Daemon is loopback-only — no auth (same as all existing routes).

### 2.1 `POST /v1/context/build` (sync JSON)

```jsonc
// Request
{
  "task": "Toss confirm 후 premium-report 접근이 안 되는 원인을 찾아줘",
  "budget": {                       // optional — shape matches ContextBudget
    "maxFiles": 8,
    "maxHotspotsPerFile": 3,
    "hotspotContextLines": 12
  },
  "extraIgnoreGlobs": []            // optional
}

// 200 OK
{
  "ok": true,
  "artifact": { /* full ContextArtifact */ },
  "promptMdWorkspacePath": ".tierkit/runtime/context-artifacts/ctx_xxx/prompt.md"
}

// 400 Bad Request
{ "ok": false,
  "code": "no-keywords" | "no-candidates" | "workspace-not-found" | "rg-missing",
  "message": "..." }
```

**Field naming note (per §2 brainstorm feedback):** `promptMdWorkspacePath` is workspace-relative (not artifact-dir-relative). This deliberately avoids the name clash with `ContextArtifact.promptMdPath` which is `"prompt.md"` (artifact-dir-relative).

**Implementation:** wraps `buildCompressedContext()` (already exported from `@tierkit/core`) + `writeArtifact()`. `workspaceRoot` is the daemon's `cwd` (loopback only sees one workspace per daemon — no request-supplied workspaceRoot).

### 2.2 `GET /v1/context/:id` (sync JSON)

```jsonc
// 200 OK
{
  "ok": true,
  "artifact": { /* ContextArtifact incl. .compare if present */ },
  "verdict": null | { /* ArtifactVerdict — see §4 */ }
}

// 404 Not Found
{ "ok": false, "code": "not-found", "message": "artifact 'ctx_xxx' not found" }
```

**Implementation:** wraps `readArtifact()` + `readVerdict()` (the latter introduced in §4).

### 2.3 `GET /v1/context/recent` (sync JSON)

```jsonc
// 200 OK
{
  "ok": true,
  "recent": [
    {
      "id": "ctx_a3b2c1d4e5",
      "createdAt": "2026-05-19T08:00:00.000Z",
      "task": "Toss confirm 후 premium-report ...",   // normalized + truncated, see below
      "candidatesCount": 5,
      "estimatedBaselineInputTokens": 72400,
      "estimatedCompressedInputTokens": 8930,
      "hasCompare": true,
      "hasVerdict": false
    }
  ],
  "totalCount": 1
}
```

**Sort:** `artifact.createdAt` DESC (per §2 brainstorm feedback — directory mtime is unreliable across file operations).

**Cap:** `RECENT_CAP = 20` (server constant). Hint shown to UI when `totalCount > 20`: list older contexts via `tierkit context show <id>` in the CLI.

**`totalCount` semantic (per §7 brainstorm feedback):** counts **valid readable artifacts only** — directories whose `artifact.json` parses successfully. Malformed / unreadable artifact directories are excluded from both `recent[]` and `totalCount`. The number reflects what the user can actually open in the UI, not raw `fs.readdir` count.

**`task` preview (per §7 brainstorm feedback):** server applies `artifact.task.replace(/\s+/g, " ").slice(0, 120)` before sending. Whitespace and newlines collapse to single spaces; first 120 chars; client adds ellipsis when truncated.

**Discovery algorithm:**

```ts
async function listRecentContexts(workspaceRoot) {
  const dir = path.join(workspaceRoot, ".tierkit/runtime/context-artifacts");
  let names: string[];
  try { names = await fs.readdir(dir); }
  catch { return { recent: [], totalCount: 0 }; }   // dir missing → empty (not error)

  const entries: { id: string; artifact: ContextArtifact; hasVerdict: boolean }[] = [];
  for (const name of names) {
    if (!/^ctx_[a-f0-9]{10}$/.test(name)) continue;
    try {
      const { artifact } = await readArtifact(workspaceRoot, name);
      const verdict = await readVerdict(workspaceRoot, name);
      entries.push({ id: name, artifact, hasVerdict: verdict !== null });
    } catch {
      // malformed artifact — skip silently; daemon log carries the warning
    }
  }

  entries.sort((a, b) =>
    (b.artifact.createdAt ?? "").localeCompare(a.artifact.createdAt ?? "")
  );

  return {
    recent: entries.slice(0, RECENT_CAP).map(toRecentEntry),
    totalCount: entries.length,
  };
}
```

**Performance:** 20 small reads + 1 dir listing per request. ~10-50ms typical. If a user has 1000s of artifacts, the walk is O(n) — acceptable for v0.12.2; an index file is a v0.13+ optimization.

### 2.4 `POST /v1/context/:id/compare` (SSE stream)

```jsonc
// Request
{
  "profileId": "claudeSonnet",
  "mode": "execute",            // optional — default "execute"
  "confirm": true               // REQUIRED — explicit safety check at HTTP layer
}

// 412 Precondition Failed (confirm missing — the 412 IS the modal preview)
{
  "ok": false,
  "code": "confirm-required",
  "message": "compare runs 2 paid model calls; pass { confirm: true } to proceed",
  "estimated": {
    "baselineInputTokens": 72400,
    "compressedInputTokens": 8930,
    "baselineInputCostUsd": 0.217,     // null if profile has no cost data
    "compressedInputCostUsd": 0.027,
    "profileId": "claudeSonnet"
  }
}

// 409 Conflict (another compare for this :id is already running)
{ "ok": false, "code": "compare-already-running",
  "message": "another compare is already running for ctx_xxx" }

// 404 / 400 standard

// 200 → switches to SSE stream (text/event-stream)
//   Headers:
//     Content-Type: text/event-stream
//     Cache-Control: no-cache
//     Connection: keep-alive
//   Body: see §3
```

**Pre-stream validation order** (per §2 brainstorm feedback): artifact existence → `confirm: true` → not-already-running → profile resolvable. Each step's failure returns a JSON error **before any SSE headers are written**. Once SSE headers are sent, all subsequent errors become SSE `error` events (HTTP status cannot be reshaped post-headers).

**Implementation:** wraps `compareCompressedContext()`. The existing usecase already takes `onPhase` / `onBaselineDelta` / `onCompressedDelta` callbacks (added in v1.7-spike). Server wires those callbacks to `res.write()` SSE event chunks. In-memory `Set<artifactId>` of running compares for 409 dedup. `AbortController` chained to `req.on("close")` for client-disconnect abort.

### 2.5 `POST /v1/context/:id/verdict` (sync JSON)

```jsonc
// Request — note: artifactId is NOT in the body; it comes from the URL
{
  "qualityVerdict": "same" | "better" | "worse" | "unusable",  // required
  "missingContext": true | false,                              // optional
  "notes": "compressed got the same root cause but missed lib/orders.ts nuance"  // optional, max 2000 chars
}

// 200 OK
{
  "ok": true,
  "verdict": {
    "artifactId":     "ctx_xxx",
    "qualityVerdict": "same",
    "missingContext": false,
    "notes": "...",
    "reviewedAt":     "2026-05-19T08:55:32.123Z"     // server-stamped, ISO with timezone
  }
}

// 409 Conflict (no compare result yet)
{ "ok": false, "code": "compare-not-run",
  "message": "verdict requires a completed compare result on this artifact" }

// 404 / 400 standard
```

**Implementation:** validates `artifact.compare !== undefined` → 409 if absent. Server builds the verdict object internally (artifactId from URL, reviewedAt from `new Date()`) — caller cannot forge either. Atomic write per §4.

### Error-code matrix (all endpoints)

| Code | Endpoints | Meaning |
|---|---|---|
| `not-found` | GET/POST `/:id` | artifact dir or `artifact.json` missing |
| `no-keywords` / `no-candidates` / `workspace-not-found` / `rg-missing` | POST `/build` | from `buildCompressedContext` result union |
| `confirm-required` | POST `/:id/compare` | body missing `confirm: true`; response includes `estimated` payload |
| `compare-already-running` | POST `/:id/compare` | another compare for the same `:id` is in flight |
| `compare-not-run` | POST `/:id/verdict` | `artifact.compare === undefined` |
| `bad-request` | any | malformed JSON / missing required field |

### `index.ts` exports

No new HTTP-shape exports (endpoints are server-internal). The verdict module exports its public types from `runtime/verdictStore.ts` — see §4.

## §3. SSE event protocol for `POST /v1/context/:id/compare`

`Content-Type: text/event-stream`. Standard SSE wire format:

```
event: <name>
data: <single-line JSON payload>

```

(double newline terminates each event)

### Event types

| Event | Payload | Emitted by |
|---|---|---|
| `phase` | `{ phase: "baseline-start" \| "baseline-end" \| "compressed-start" \| "compressed-end" }` | `compareCompressedContext.onPhase` |
| `delta` | `{ side: "baseline" \| "compressed", text: "<chunk>" }` | `onBaselineDelta` / `onCompressedDelta` |
| `side-result` | `{ side, actualInputTokens?, actualOutputTokens?, actualCostUsd?, latencyMs?, failureCode?: string }` | Server, after each `runOneSide` returns |
| `compare-done` | `{ compare: CompareResult, artifact: ContextArtifact }` | Server, after `mutateArtifact` succeeds |
| `error` | `{ code: string, message: string, side?: "baseline" \| "compressed" }` | Any structural failure or unexpected exception |

**`side-result` fields are all optional** (per §3 brainstorm feedback): provider usage may be missing in some failure / partial cases. The UI shows `—` when a value is absent.

**`error.side`** (renamed from `error.phase` per §3 brainstorm feedback) carries which side of the compare the error occurred on. Naming matches the existing `side: "baseline" | "compressed"` discriminator used in `delta` and `side-result`.

**Keepalive:** server writes a comment line `:\n\n` every 15s to defeat proxy idle-close. EventSource (and any sane SSE parser) ignores comments.

### Happy-path ordering

```
event: phase
data: {"phase":"baseline-start"}

event: delta
data: {"side":"baseline","text":"The root cause is at line 47..."}

... many baseline delta events ...

event: phase
data: {"phase":"baseline-end"}

event: side-result
data: {"side":"baseline","actualInputTokens":71892,"actualOutputTokens":412,"actualCostUsd":0.215,"latencyMs":4201}

event: phase
data: {"phase":"compressed-start"}

event: delta
data: {"side":"compressed","text":"..."}

... many compressed delta events ...

event: phase
data: {"phase":"compressed-end"}

event: side-result
data: {"side":"compressed","actualInputTokens":9142,"actualOutputTokens":387,"actualCostUsd":0.014,"latencyMs":1840}

event: compare-done
data: {"compare":{...full CompareResult...},"artifact":{...full updated ContextArtifact...}}
```

Stream then closes cleanly. `compare-done` is the terminator.

### Error scenarios

**Structural baseline failure** (`runRoute` returns `ok: false` — e.g., `unknown-profile`, `budget-exceeded`):

```
event: phase
data: {"phase":"baseline-start"}

event: error
data: {"code":"unknown-profile","message":"no profile claudeSonnetX","side":"baseline"}
```

Stream closes. No baseline-end, no side-result, no compressed phase. `artifact.json` NOT mutated.

**Mid-stream baseline error** (stream emits `error` event mid-call; per existing `compareCompressedContext` semantics, processing continues to next phase):

```
... baseline phase events ...
event: phase
data: {"phase":"baseline-end"}

event: side-result
data: {"side":"baseline","actualInputTokens":...,...,"failureCode":"stream-error"}

event: phase
data: {"phase":"compressed-start"}

... compressed proceeds normally ...

event: compare-done
data: {"compare":{...},"artifact":{...}}
```

`side-result.failureCode` carries the reason; final `compare-done` records the partial result.

**Compressed-side structural failure** (after baseline succeeded):

```
... baseline events normally ...

event: phase
data: {"phase":"compressed-start"}

event: error
data: {"code":"...","message":"...","side":"compressed"}
```

Stream closes. **`response-baseline.md` may exist on disk** (it was written when baseline succeeded), but `artifact.json` `compare` field is NOT updated (consistent with existing `compareCompressedContext` semantics — partial compare is not stored). UI displays "Compare failed during compressed phase. Baseline response was saved, but no compare result was recorded." (see §6).

### Client disconnect

When SSE client disconnects (`req.on("close")`), server:

1. Calls `AbortController.abort()` on the in-flight compare.
2. Removes the artifact from the `runningCompares` Set so a retry is accepted.
3. Does NOT continue baseline/compressed calls in the background. Best-effort abort only.

**Cost caveat:** if the disconnect happens after a provider call has already left the daemon, the underlying API call may complete on the provider side and incur tokens/cost on the user's account. Tierkit cannot rescind a provider call once initiated. Applies equally to CLI `^C` during `tierkit context compare`.

### Backpressure (limitation documented)

v0.12.2 does NOT implement explicit `res.write()` drain-await beyond Node's internal buffering. Server writes events as they arrive from the upstream provider stream. For typical compare response sizes (single-digit to low-hundreds of KB per side), Node's default buffering is sufficient. If validation reveals stalls or memory pressure with pathological response sizes, v0.12.3 can add explicit `await once(res, "drain")` handling.

### SSE data format constraint (documented)

Server emits **single-line JSON `data:` payloads only**. Multiline SSE `data:` (where consecutive `data:` lines are joined by `\n`) is not supported in v0.12.2. This simplifies the client parser. If a delta text contains newlines, they are JSON-encoded as `\n` within the single-line JSON string.

### Client helper

Inline in `gui.ts`, ~40 LOC, named `streamSsePost(url, body, handlers, abortSignal)` (per §3 brainstorm feedback). See §5 for the full implementation.

### `index.ts` exports for the protocol shapes

```ts
// packages/core/src/runtime/compareSseEvents.ts (small new type file)
export type CompareSsePhase = "baseline-start" | "baseline-end" | "compressed-start" | "compressed-end";
export type CompareSseSide = "baseline" | "compressed";

export type CompareSseEvent =
  | { event: "phase";        data: { phase: CompareSsePhase } }
  | { event: "delta";        data: { side: CompareSseSide; text: string } }
  | { event: "side-result";  data: {
      side: CompareSseSide;
      actualInputTokens?: number;
      actualOutputTokens?: number;
      actualCostUsd?: number;
      latencyMs?: number;
      failureCode?: string;
    } }
  | { event: "compare-done"; data: { compare: CompareResult; artifact: ContextArtifact } }
  | { event: "error";        data: { code: string; message: string; side?: CompareSseSide } };
```

Exported from `@tierkit/core` barrel for future TypeScript SSE consumers. v0.12.2 GUI parses event names by string directly (no type import needed inside the inline `<script>` block).

## §4. Verdict storage (sidecar `verdict.json`)

### File path

```
.tierkit/runtime/context-artifacts/<id>/verdict.json
```

Sibling of `artifact.json`. `.tierkit/.gitignore` (from v1.7-spike) already covers it.

### Schema

```ts
// packages/core/src/runtime/verdictStore.ts (new module)

export const QUALITY_VERDICTS = ["same", "better", "worse", "unusable"] as const;
export type QualityVerdict = (typeof QUALITY_VERDICTS)[number];

/**
 * Human quality judgment on a context-compression compare result.
 *
 * qualityVerdict semantics:
 *   same     — compressed response preserves the SAME USEFUL OUTCOME as baseline.
 *              NOT text equality — phrasing/wording can differ freely.
 *   better   — compressed response is meaningfully better than baseline.
 *              Compression removed noise; reasoning clearer. Rare but observed.
 *   worse    — compressed response missed something baseline got, or introduced
 *              a wrong claim, but still partially useful.
 *   unusable — compressed response is materially wrong / misleading / would
 *              cause harm if acted on. Compression should not have been used
 *              for this task.
 *
 * Aggregated verdicts feed the validation-log compilation that gates v0.14
 * (local LLM rerank/compress) entry. See the v1.7-spike validation log spec.
 */
export const VerdictSchema = z.object({
  artifactId:     z.string().regex(/^ctx_[a-f0-9]{10}$/),
  qualityVerdict: z.enum(QUALITY_VERDICTS),
  missingContext: z.boolean().optional(),
  notes:          z.string().max(2000).optional(),
  reviewedAt:     z.string().datetime(),    // ISO 8601, server-stamped at write time
}).strict();

export type ArtifactVerdict = z.infer<typeof VerdictSchema>;
```

### Module API

```ts
export class VerdictStoreError extends Error {
  code: "not-found" | "schema-mismatch" | "compare-not-run" | "artifact-not-found";
}

/** Read verdict.json sidecar. Returns null when the file is absent (NOT an error). */
export async function readVerdict(
  workspaceRoot: string,
  artifactId: string,
): Promise<ArtifactVerdict | null>;

/**
 * Write the verdict. REQUIRES `artifact.json` exists AND has a `compare` field set
 * (else throws VerdictStoreError "artifact-not-found" or "compare-not-run").
 *
 * Server builds the verdict object internally — artifactId comes from the
 * `artifactId` parameter (URL :id), reviewedAt is server-stamped to ISO now.
 * Callers cannot forge either.
 *
 * Atomic write: writes `verdict.json.tmp` then renames. Last-write-wins
 * (overwrites existing verdict).
 */
export async function writeVerdict(
  workspaceRoot: string,
  artifactId: string,
  input: {
    qualityVerdict: QualityVerdict;
    missingContext?: boolean;
    notes?: string;
  },
): Promise<ArtifactVerdict>;
```

### Read semantics (lenient)

- File missing → returns `null`. Not an error — most artifacts never get a verdict.
- File present but invalid JSON → returns `null`. Daemon logs **one** warning line at WARN level with the artifact id and the full path:
  ```
  Warning: invalid verdict.json for ctx_a3b2c1d4e5 at /Users/.../verdict.json; treating as no verdict.
  ```
- File present but schema mismatch (e.g., future-version verdict written by a newer Tierkit) → returns `null`, logs warning with the same format.

Rationale: verdict is annotation, not source data. Corrupted verdict shouldn't prevent the user from re-running compare or saving a new one. The new write overwrites the corruption.

### Write semantics (strict)

- Artifact directory must exist → else throws `VerdictStoreError("artifact-not-found")`.
- `artifact.json` must have `compare !== undefined` → else throws `VerdictStoreError("compare-not-run")`.
- Input `qualityVerdict` must be one of the 4 enum values (zod validates).
- `notes` ≤ 2000 chars (zod enforces).
- `reviewedAt` always server-stamped at write time (`new Date().toISOString()`).
- Atomic write: `fs.writeFile(verdict.json.tmp)` → `fs.rename(verdict.json.tmp, verdict.json)`.

### Versioning

v0.12.2 verdict has no `schemaVersion` field — implicit v1. Future schema versioning requires a migration-aware reader (introduce `schemaVersion: z.literal(1).default(1)` at that point and migrate-on-read for older shapes). Not a concern in v0.12.2.

### HTTP integration

- `POST /v1/context/:id/verdict` → calls `writeVerdict` → maps thrown `VerdictStoreError`:
  - `artifact-not-found` → 404
  - `compare-not-run` → 409
- `GET /v1/context/:id` → calls `readVerdict` → puts result into response under `verdict: ArtifactVerdict | null`.

### CLI surface

**Not in v0.12.2 scope.** Users record verdicts via the GUI. Users CAN manually inspect `verdict.json` files on disk for validation-log compilation. A future `tierkit validation-log` command could aggregate verdicts into the markdown log — that's a v0.13 polish candidate.

### `index.ts` exports

```ts
export {
  QUALITY_VERDICTS,
  type QualityVerdict,
  VerdictSchema,
  type ArtifactVerdict,
  readVerdict,
  writeVerdict,
  VerdictStoreError,
} from "./runtime/verdictStore.js";
```

### Backward compatibility

- No `ContextArtifact` schema change. No `schemaVersion` bump.
- Old artifacts with no `verdict.json` → `GET /v1/context/:id` returns `verdict: null`.

### Test surface

- `verdictStore.test.ts`:
  - write + read roundtrip
  - read returns `null` on missing file (not error)
  - read returns `null` + log on invalid JSON
  - read returns `null` + log on schema mismatch
  - write throws `artifact-not-found` when `artifact.json` missing
  - write throws `compare-not-run` when `artifact.compare === undefined`
  - write overwrites existing verdict; `reviewedAt` updates
  - atomic write (verify `.tmp` is gone after success)
  - `notes` > 2000 chars → zod rejects

## §5. GUI cards / data flow

### Card location

Activates the existing inert stub from v0.11.2: "Current project" group → renamed "Current project — validation" card. Same card slot, now functional.

Card title (EN): `Current project — validation`. Korean: `현재 프로젝트 — 검증`.

DOM id prefix: `c122-`.

### Card states

8 states. State transitions are entirely client-side; backend is stateless per request.

| State | Trigger | Visible |
|---|---|---|
| **A. Empty** | First load, no recent contexts | Task textarea + Build button. "No previous contexts yet." |
| **B. Empty with history** | First load, recent contexts exist | Task textarea + Build button + Recent contexts dropdown above |
| **C. Building** | After Build clicked | Spinner + "Building compressed context (no model call)..." |
| **D. Built, no compare** | After build success / loading existing artifact | Token estimates + selected-files list + path display + profile picker + Compare button |
| **E. Compare running** | After modal confirm | Two-column live streaming responses + progress + Cancel button |
| **F. Compare done (success)** | SSE `compare-done` event | Response viewer + savings table + verdict controls + Save verdict |
| **G. Verdict saved** | After verdict save success | Compact "verdict: same · 2026-05-19 08:55" line + Edit verdict button |
| **H. Compare failed/partial** | SSE `error` event mid-stream | Same response viewer + savings table (whichever partial data exists), no verdict controls, error banner above |

State F renders verdict controls. State H reuses the same response viewer layout but **hides** verdict controls — partial compares cannot be verdict-rated.

### Card layout (state D / F shown)

### Data flow per state transition

```
Initial load (refreshValidationCard):
  → GET /v1/context/recent
  → if recent.length > 0: populate dropdown + GET /v1/context/<latest>; render D/F/G/H per state
  → else: render State A

Click Build:
  → POST /v1/context/build { task }
  → on 200: render State D (with the new artifact)
  → on 400: show inline error ("no keywords" / "no candidates" / "rg-missing")
  → button disabled during in-flight (re-enabled on response)

Click Recent dropdown entry:
  → GET /v1/context/<chosenId>
  → on 200: render state D / F / G / H based on artifact.compare and verdict presence
  → on 404: inline error "Context no longer on disk"; refresh dropdown
  → update currentArtifactId (session-only, no storage)

Click Compare (state D):
  → button disabled
  → POST /v1/context/:id/compare { profileId, mode: "execute" }   ← no confirm
  → expect 412 with estimated payload
  → populate modal, show overlay (Cancel button focused)
  → on Cancel (or Esc): close modal, re-enable Compare button, stay in D
  → on Run compare:
      → close modal
      → streamSsePost(`/v1/context/:id/compare`, { ..., confirm: true }, handlers, abortSignal)
      → transition to State E
      → handlers route events into renderer
      → on compare-done: render State F
      → on error (post-stream): render State H + error banner
      → on connection close without compare-done or error: render State D + "Compare cancelled. If a provider call had already started, some tokens may still be billed."

Click Cancel (state E):
  → abortSignal.abort() → fetch cancels
  → server: req.on("close") → AbortController.abort() on compare
  → UI: render State D + "Compare cancelled. If a provider call had already started, some tokens may still be billed."

Select verdict + click Save verdict (state F):
  → button disabled until qualityVerdict radio chosen
  → notes counter turns red and Save disabled when > 2000 chars (NO auto-truncate)
  → POST /v1/context/:id/verdict { qualityVerdict, missingContext, notes }
  → on 200: render State G with saved verdict echo
  → on 409 compare-not-run: defensive error (button shouldn't be enabled in this state)

  → render State F, pre-populated from current verdict
  → Save overwrites
```

### `streamSsePost` helper (inline in `gui.ts`)

```js
/**
 * POST with text/event-stream response. Parses each \n\n-delimited block as
 * one SSE event (single-line JSON data: only — see §3). Calls the matching
 * handler.* per event name. Aborts on the supplied AbortSignal.
 *
 * Assumes server emits SINGLE-LINE JSON data: payloads. Multiline SSE data
 * (where consecutive `data:` lines join with \n) is NOT supported in v0.12.2.
 */
async function streamSsePost(url, body, handlers, abortSignal) {
  let res;
  try {
    res = await fetch(url, {
      method: "POST",
      headers: { "Content-Type": "application/json", "Accept": "text/event-stream" },
      body: JSON.stringify(body),
      signal: abortSignal,
    });
  } catch (err) {
    if (err.name === "AbortError") return;
    handlers.onError?.({ code: "fetch-failed", message: String(err.message ?? err) });
    return;
  }

  if (!res.ok) {
    // Pre-stream JSON error path (404 / 409 / 412 / 400)
    let err;
    try { err = await res.json(); }
    catch { err = { code: "http-" + res.status, message: res.statusText }; }
    handlers.onError?.(err);
    return;
  }

  const reader = res.body.getReader();
  const decoder = new TextDecoder();
  let buffer = "";

  while (true) {
    const { value, done } = await reader.read();
    if (done) break;
    // Normalize line endings — some intermediaries (e.g., dev proxies) may inject CRLF.
    buffer += decoder.decode(value, { stream: true }).replace(/\r\n/g, "\n");
    let chunkEnd;
    while ((chunkEnd = buffer.indexOf("\n\n")) >= 0) {
      const raw = buffer.slice(0, chunkEnd);
      buffer = buffer.slice(chunkEnd + 2);
      if (raw.startsWith(":")) continue;   // SSE comment / keepalive — ignore
      const evt = parseSseChunk(raw);
      switch (evt.event) {
        case "phase":        handlers.onPhase?.(evt.data);        break;
        case "delta":        handlers.onDelta?.(evt.data);        break;
        case "side-result":  handlers.onSideResult?.(evt.data);   break;
        case "compare-done": handlers.onCompareDone?.(evt.data);  break;
        case "error":        handlers.onError?.(evt.data);        break;
      }
    }
  }
}

function parseSseChunk(raw) {
  const lines = raw.split("\n");
  let event = "message";
  let data = "";
  for (const line of lines) {
    if (line.startsWith("event:")) event = line.slice(6).trim();
    else if (line.startsWith("data:")) data += line.slice(5).trim();
  }
  return { event, data: data ? JSON.parse(data) : undefined };
}
```

## §6. Confirmation modal flow + edge cases

### Modal flow (Compare button only)

```
User clicks [Compare] (state D)
  │
  ▼
[1] Disable Compare button immediately (prevent double-click)
  │
  ▼
[2] POST /v1/context/:id/compare WITHOUT confirm  ──► server returns 412 + estimated payload
  │                                                       │
  │                                                       └► Modal populates from estimated
  ▼
[3] Render modal overlay, focus the Cancel button
  │
  ├── User clicks [Cancel] / presses Esc
  │    → close modal, re-enable Compare button → back to state D
  │
  └── User clicks [Run compare]
       │
       ▼
      [4] Close modal, transition to state E
       │
       ▼
      [5] streamSsePost(`/v1/context/:id/compare`, { profileId, mode, confirm: true }, handlers, abortSignal)
       │
       ▼
      [6] On compare-done → state F
          On error → state H + error banner
          On disconnect (cancel) → state D + cancelled note
```

### Keyboard

- `Esc` while modal open → same as Cancel
- `Enter` while modal open → does **nothing** (avoid accidental run)
- Tab order: Cancel (default focus) → Run compare

### Edge cases

| Scenario | UI behavior |
|---|---|
| Profile dropdown empty (no `modelProfiles`) | Compare disabled. Hint: "Configure a model profile to enable compare." |
| Profile has no `apiKeyEnv` env value | Compare still enabled. Inline hint beneath button: `ⓘ Selected profile may require an API key. Tierkit will surface provider errors if authentication fails.` Failure surfaces as SSE error event with provider's auth error. |
| Profile has no `cost` data | Modal shows tokens but `est cost: unknown`. User can proceed. |
| `/v1/context/:id` 404 between dropdown select and detail render | Inline error "Context no longer on disk"; refresh dropdown; fallback to state A/B |
| Daemon unreachable when clicking Build / Compare | Inline error "Daemon offline — check `tierkit runtime status`." Button re-enables. |
| User refreshes sidebar mid-compare (browser Cmd+R) | SSE closes → server aborts. Next load: state D (no compare result saved). |
| Compare returns 409 `compare-already-running` (e.g., 2 sidebars open) | Modal closes, inline error "Another compare is running. Wait or cancel in the other window." |
| Compare returns SSE `error` event mid-stream | State H. Response viewer renders partial data. Verdict controls hidden. Error banner above with code + message. |

| Multiple recent artifacts deleted on disk during session | Each 404 selection shows inline error; dropdown stays populated (race is unavoidable). |
| Compare cancelled via Cancel button (state E) | UI shows: `Compare cancelled. If a provider call had already started, some tokens may still be billed.` (in `c122-cancelled-note`). |

## Note for the implementation plan

When writing-plans generates the v0.12.2 plan, decompose into the following phases. Each phase ships independently green; this keeps the PR sequence reviewable:

1. **Phase 1 — Verdict store** (verdictStore module + 8 tests). No HTTP, no GUI. Self-contained.
2. **Phase 2 — HTTP endpoints (sync)** — build / `:id` / recent / verdict. Skip compare (Phase 3). Each endpoint with at least one HTTP integration test.
3. **Phase 3 — SSE compare endpoint** — wire `compareCompressedContext` callbacks to SSE events; in-flight dedup Set; AbortController on disconnect; SSE event-flow integration test.
4. **Phase 4 — GUI validation card** — new card markup, state machine, `streamSsePost` helper, modal, verdict controls, i18n keys, build-smoke test.
5. **Phase 5 — Docs + release** — README/SPEC/CHANGELOG + memory note + version bump.

Phases 1-3 can land in main individually without UI access (CLI continues to work; HTTP endpoints exist but unused). Phase 4 activates the UI surface. Phase 5 closes the release.

Single-PR delivery is also acceptable if reviewer prefers fewer commits, but the phase boundaries above remain useful as commit boundaries within the PR.
