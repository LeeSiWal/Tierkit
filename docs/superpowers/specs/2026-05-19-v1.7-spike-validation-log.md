## Failure classification

If a task scored PARTIAL or FAIL, classify the root cause. **First check: did baseline also fail?**

### A. Baseline also failed (NOT a Tierkit problem)

- [ ] Task too hard for the model regardless of context
- [ ] Task ambiguous / underspecified
- [ ] Required information was outside the selected files (baseline used selected files only, not full repo)
- Conclusion: discard this case from compression-quality scoring; consider re-running with a more specific task or larger `--max-files`

### B. Baseline succeeded, compressed failed (Tierkit compression problem)

Pick ALL that apply:

- [ ] **Candidate selection** — relevant file wasn't in `candidates[]`
  - Was `extractKeywords` reasonable? _(check `tierkit context show <id>`)_
  - Were keywords too generic? Did the relevant file have no keyword hits?
  - Fix in v1.8: better ranking / import graph expansion / local LLM file-ranker
- [ ] **Skeleton too thin** — the right symbol/function was visible but signature alone wasn't enough
  - Fix in v1.8: tree-sitter for richer skeleton / longer signature context
- [ ] **Hotspot missed the critical lines** — keyword matched but the wrong window
  - Bumping `--hotspot-lines` or `--max-hotspots` helps?
  - Fix in v1.8: smarter hotspot scoring (proximity to control flow boundaries, not just match density)
- [ ] **prompt.md template lost signal** — file was selected, hotspots were right, but the template formatting confused the model
  - Compare baseline.md and prompt.md for the same file — does prompt.md make the connections obvious?
  - Fix in v1.8: cloud-prompt-builder role (LLM-generated final prompt)
- [ ] **Task keyword extraction problem** — task wording produced poor keywords
  - Re-run with more identifiers/quoted phrases in the task string
  - Fix in v1.8: optional task rewriter
- [ ] **Diff/log absence** (Tasks 4, 5) — error message or diff context not provided
  - v1.8 priority: diff/log input compression

### C. Compressed accidentally did better than baseline

Note this — it usually means baseline got drowned in noise. Helpful signal: when this happens consistently, compression *improves* quality, not just cost.
